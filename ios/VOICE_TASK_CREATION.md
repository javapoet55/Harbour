# Continuous Add by Voice

Tasks → Add by Voice starts one WebRTC Realtime session after consent and microphone permission. `gpt-realtime-2.1` handles conversation, tools and spoken replies (Marin); `gpt-live-transcribe` supplies the displayed input text.

The active screen uses `VoiceConversationSession`, `VoiceWebRTCTransport`, and `VoiceToolExecutor`. The former single-task `VoiceTaskController` is no longer used. Tasks are saved via authenticated backend tools and reconciled into the app. Replies follow successful tool output, then the screen returns to listening automatically. Corrections resolve “last” to the most recently modified task ID. No microphone tap is required between turns.

Semantic VAD detects turns. The client requests responses on committed input, suppresses duplicate commits, cancels and clears interrupted playback, and rejects tool calls from interrupted responses. Playback completion, rather than generation completion, controls the transition back to listening. A readiness bell is bundled; Done has a white label.

Conversation states are event-driven. Muting is tracked separately from response/tool progress so in-flight saves can finish. The UI timer only checks configurable deadlines. A transient ICE disconnect gets an eight-second recovery window. Confirmed failures wait for a usable network path and make up to three new WebRTC connections with fresh credentials. Recovery retains the logical session ID, idempotency keys, saved tasks, and clarification context, then supplies that context to the replacement Realtime session. In-flight mutations finish without sending stale call output to the replacement connection. Backgrounding mutes audio immediately and closes after the configured grace period. Phone-call interruptions pause and resume the audio session, and headset route changes reactivate it without discarding the conversation. Closing by voice waits for goodbye playback. A failed save is reported and is not automatically retried.

Validation includes native scripted recovery coverage for reconnect context, in-flight mutations, audio interruptions, multiple tasks, correction, graceful goodbye, barge-in, cancellation, mute, and timeouts. The full Swift suite and the original Harbour iOS simulator build pass. Mocked service events cover deterministic state transitions; live iPhone/OpenAI conversation quality and route handoffs still require physical-device verification.
