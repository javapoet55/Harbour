# Shopping List store lookup

List Settings opens a dedicated Stores Near You picker through Add New Store. It searches Google Places by city or ZIP code with an optional store-name filter (600 ms debounce). With no name filter it searches for grocery stores. Alternatively, the user can tap Use my location to request a one-time approximate location. ZIP or city takes precedence when present. The picker uses NexDo styling, store icons, full addresses and Add buttons. Straight-line distances are shown only for device-coordinate searches; city/ZIP searches do not invent a distance. Already-authorized approximate location is used when opening without a ZIP; otherwise users can explicitly request permission or type a location. Selecting Add returns to List Settings and fills the store name, full formatted address and the branch's postal code; the usual Save button persists them. Search does not save automatically. Manual entry remains available.

The authenticated POST /api/shopping/stores endpoint uses the existing server-only GOOGLE_PLACES_API_KEY and Places API (New) Text Search. Enable that API and billing on the key's Google Cloud project. Never bundle the key in iOS. The existing durable account rate limiter allows 30 lookups per minute; normal signup abuse/session configuration remains required. Results are not cached, closed businesses are excluded, and requests time out after 12 seconds. Search results display Google Maps attribution and any returned provider names.

Deploy the backend route and rebuild the iOS application together. No database migration or worker change is needed. Store discovery does not enable an unsupported store's offer collector.

Validation: mocked provider tests cover ZIP precedence, coordinate bias, address/postal-code mapping, closed stores, validation, missing key and upstream errors; route tests cover authentication, validation and rate limits. Real Google account/API access must be checked in the deployed environment.
